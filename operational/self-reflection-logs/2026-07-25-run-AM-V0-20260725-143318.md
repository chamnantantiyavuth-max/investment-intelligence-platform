## 5. Lessons

### L1 — Real EOD Exposes Fixture Optimism Bias
The single most valuable thing real EOD did was catch INTC's stage misclassification. Synthetic fixtures, written with domain knowledge, encode the fixture author's thesis expectations — they describe what the author *wants* to be true, not what the market *prices as* true. Real data is the antidote.

**Principle:** Every candidate, theme, and assessment must eventually be validated against real market data. Synthetic fixtures are for pipeline construction — real data is for thesis validation.

### L2 — Phase Upgrades Are Safe When Architecture is Enrichment-Only
Phase 7 Q-Conditions integrated without breaking anything because the pipeline architecture (enrich + group, never filter) is robust to additive changes. The S1-S6 stages never reject candidates — they only add labels. This means new features (Exit Rules, Lifecycle States) can be layered on without threatening existing functionality.

**Lesson from prior SRLs confirmed:** The architecture decision to make all pre-S6 stages enrichment-only (Gate A, DS-501 through DS-505) was correct. It future-proofs against exactly this kind of phased feature addition.

### L3 — Cross-Module Synchronization Needs Automation
`source_adapter.py` and `fixtures.py` diverged silently. No test, no lint, no verification caught that 4 candidates had no real EOD path. The pipeline happily ran with partial data.

**Recommendation:** Add a pre-flight check: `if len(fixture_candidates) != len(V0_TICKERS) --> warn`. This is a 3-line change to `run_real.py` that prevents silent data gaps.

### L4 — Temporal Mismatch Between Fixtures and Real Data Is a Structural Issue
Fixtures have hardcoded point-in-time (2024-07-01). Real EOD is always current. The pipeline's `point_in_time` field now shows the run date (2026-07-25) but the fixture's internal assessments (Stage, RS, fundamentals) are frozen at 2024-07-01. When the two disagree (as with INTC), the pipeline has no way to reconcile them.

**Recommendation for Phase 8+:** Real EOD should be the authoritative source for market-derived fields (price, stage, RS, volume behavior). Fixture data should only fill non-market fields (thesis narrative, role classification, key risks). This requires a stage detection algorithm — Minervini's trend template or Weinstein's stage analysis — which is deferred per Phase 7 scope (Rule Pack spec only, no implementation).

### L5 — Blind Spot Persistence Is Now Structural
All 5 blind spots from SRL v0.2 (2024-07-24) are still present: single healthcare theme, no small/mid-cap, uniform stage distribution, no non-US exposure, no programmatic thesis invalidation. These are not bugs to fix — they are scope limitations of V0. But the fact that 2 SRLs and 2 pipeline runs have passed without addressing them means they have become **structural blind spots** — features of the V0 design, not temporary gaps.

**Recommendation:** In SRL v0.2, these were presented as "Blind Spots." After 2 runs without resolution, reclassify them as "Known V0 Scope Limitations" — distinct from Blind Spots which imply discoverability. The next material change to address them requires Phase 8 (Fundamental & Opportunity) or explicit Founder direction.
