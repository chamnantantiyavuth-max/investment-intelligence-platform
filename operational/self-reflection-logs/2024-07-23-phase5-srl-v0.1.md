## 3. Surprises

**Positive:** The parallel pipeline approach for experimental themes (reusing S1-S6 stages as a function, not modifying them) was cleaner than expected. Zero cross-contamination between main and experimental queues in all tests. This pattern can be reused for any future theme classification split.

**Neutral:** The inbox anomalies naturally connected to existing themes (AN-001→TH-014, AN-002→TH-004, AN-003→TH-030, AN-004→TH-010). This validates that the anomaly detection framework, even with synthetic data, produces coherent signals that reference real system state.

**Concerning:** The coverage gap report surfaced 5 gaps from a system with only 5 themes — suggesting that gap detection will scale linearly with theme count. At 143 themes (Gate B), the gap volume could be overwhelming. Need to consider prioritization/filtering before scaling.

## 4. Mistakes Identified

**Mistake:** Initial patch on `display.py` nested new functions inside `_enrich_candidates()` due to incorrect indentation in the old_string match. Required a full file rewrite to fix.

**Root cause:** The patch tool matched on `def render_theme_cards` which appeared inside the old `_enrich_candidates` body after a prior partial edit. Lesson: after a patch fails or produces unexpected nesting, read the full file before attempting a second patch.

**What should have been done differently:** After the first patch produced corrupted nesting, I should have immediately done a full `write_file` instead of attempting a second `patch`. The `write_file` approach was cleaner and eliminated the nesting risk.

## 5. Lessons

**L1 — Parallel Pipeline Pattern:** Running the same stage functions on a different dataset (experimental themes) without modifying the stage logic is a clean, testable pattern. Future strategy modules (Close System, Fundamental) can reuse this approach: call the pipeline with strategy-specific fixtures, never modify shared stages.

**L2 — Operational vs Code Boundaries:** 5C and 5D are operational templates — they have zero code dependencies. This is the right boundary for AI-assisted intelligence: the AI produces markdown, the Founder reviews, the system doesn't automatically act. Keep this separation clear in future phases.

**L3 — Inbox→Theme Pipeline:** The inbox anomalies already reference specific themes and tickers. A natural next step is a "Promote to Experimental Theme" workflow where an inbox hypothesis (e.g., HY-001 AI Edge Computing) becomes an experimental theme with one click. This is deferred to Phase 8 but the data model already supports it.

**L4 — Verification Script Pattern:** The `hermes-verify-*.py` pattern (temp file, run, clean up) works well for ad-hoc verification. The 8-AC and 9-AC scripts caught issues that `python run.py` alone would miss (e.g., cross-contamination check, field validation).

## 6. Open Questions

1. **Gap Volume at Scale:** At 143 themes, will coverage gap detection produce 50+ gaps per run? If so, need a severity filter or Founder-configurable threshold before Phase 8.

2. **Experimental Theme Lifecycle:** When should an experimental theme be promoted to Approved vs archived? The spec says "Founder approves" but doesn't define the criteria. Should the AI recommend promotion based on evidence accumulation, or is this purely Founder judgment?

3. **Inbox Staleness:** Anomalies and hypotheses have no expiration. Should they auto-stale after N days without action? The Constitution's 3-year narrative default (§8) seems too long for market anomalies.

4. **Self-Reflection Log Cadence:** Should logs be per-pipeline-run, per-session, or per-material-change? Today's log covers a full Phase implementation — that's a different granularity than a weekly pipeline run.

5. **Emergent Rule ERP-001:** Is sector concentration awareness valuable at V0 scale (5 themes) or is it noise until the theme set expands?

1. **TH-030 Cybersecurity has 0 candidates** despite AN-003 showing institutional accumulation in CRWD/PANW/ZS. The anomaly inbox is signaling but no action has been taken.

3. **No Financials/Energy/Industrials coverage** — all 5 approved themes are Tech + Healthcare. This is a conscious V0 scope decision, but it's a blind spot relative to the 143-theme controlled set.

4. **The inbox hypotheses (HY-001 AI Edge, HY-002 Water, HY-003 Robotics) have no promotion path yet.** They sit in the inbox with no workflow to become experimental themes. This is a process gap, not a data gap.

5. **No mechanism to track Founder decisions on gaps.** The coverage gap report asks 5 yes/no questions — the system has no way to record the answers. This creates a feedback loop blind spot: AI detects gaps, Founder decides, but the AI never learns which decisions were made or why.
