WHAT CHANGED IN THIS COMMIT (the target of this review)
============================================================
ONE bounded structural refactor of the M6.6 evidence-admission / reconciliation / disposition
failure-handling boundary in `qad/m6/source_bridge.py`:

1. A CLOSED, EXHAUSTIVE decision structure replaces the nested catch-all:
     EvidenceAdmissionClassification = ADMITTED_NEW | RECONCILED_IDENTICAL | TRANSIENT_PARTIAL
                                       | CONFLICT_INCOMPLETE | CONFLICT_DIVERGENT
   `EvidenceAdmissionDecision.classification` + `.settled` (only ADMITTED_NEW /
   RECONCILED_IDENTICAL / TRANSIENT_PARTIAL may settle a candidate durably).
2. THREE separated, individually testable operations replace the one nested block:
     A `attempt_canonical_evidence_admission(...)` — the EXISTING authoritative gate only; on
        failure it ROUTES the error (never classifies) to the classifier.
     B `reconcile_canonical_evidence_pair(...)` — authoritative read-back (registry.contains /
        registry.load) + EXACT-record identity comparison, returning `CanonicalPairState`.
     C `dispose_settled_candidate(...)` — writes the ONE durable disposition ONLY for a settled
        classification; an unsettled one is propagated as a typed conflict.
   `construct_candidate_evidence(...)` is the documented PRE-BOUNDARY, mutation-free stage.
3. `classify_evidence_admission_failure(...)` — the classifier. Decided from authoritative
   read-back, never from the exception type alone:
     - `SourceBridgeError` (proof / binding / verification / governance) -> re-raised (fail closed)
     - neither record exists -> TRANSIENT_PARTIAL **only** for `_RETRYABLE_OPERATIONAL_FAILURES`
       (= (TransactionFailure,)); any other error -> re-raised (fail closed)
     - exactly one record exists -> CONFLICT_INCOMPLETE -> `SourceEvidenceIncomplete`
     - both exist and match exactly -> RECONCILED_IDENTICAL
     - both exist and differ -> CONFLICT_DIVERGENT -> `SourceEvidenceConflict`
     - a failure while reading the authoritative stored state -> propagates (fail closed)
4. Reconciliation now requires FULL canonical identity, not matching ids: stored EV.evidence_id,
   stored EAR.admission_id, stored EAR.evidence_id == EV.evidence_id, stored EV.source_id == the
   verified source, and BOTH `compute_canonical_hash` values equal.
5. New tests appended (41 existing M6.6 tests retained UNCHANGED): a 15-case table-driven
   classifier table, an allowlist-narrowness test, an AST test that no broad handler in the
   refactored region can classify/downgrade, and behavioural rows 13/14/17/18 plus an
   operations-A/B/C separation test.
