VERDICT: C
M6.1 FAIL / CONTRACT-LEVEL OR CORRECTNESS DEFECT

ANSWERS:

B1. Archive-level identity binding is correctly enforced at creation and through `verify_admission_attestation`: admission uses the resolved source ID and constructs the SRC-01 reference; verification supplies both expected identity values. However, it is not complete across the public verification surface: `verify_attestation_binding` makes both identity arguments optional, and skips those checks when they are omitted. Since this helper is publicly re-exported, same-byte evidence can pass its checks without binding to the authoritative source identity. The swapped-identity test exercises only the archive method, not this bypass. (reference.py:808-810, 878-885, 913-933; attestation.py:109-122, 125-153; persistence/__init__.py:50-57, 143-148; test_m61_archive_attestation.py:111-119)

B2. The test uses a real `SourceVersion`/SRCV-01 record and the evaluator returns `SRCV_ONLY_CAPTURE_PROOF` when the attestation is absent. But classification is not fully correct: `_has_version_records` treats a non-empty `list_versions(source_id)` as SRCV evidence, while M5.2 explicitly distinguishes RawSourceArchive’s `store_version`/`list_versions` API from SRCV-01 and forbids inferring they are equivalent. Thus an unattested source with archive version snapshots but no SRCV-01 record can receive the wrong verdict. It remains ineligible, so this path fails closed on eligibility, but not on classification. (test_m61_archive_attestation.py:247-258; eligibility.py:37-56, 70-78; reference.py:570-572, 661-680; QAD-M5.2-PERSISTENCE-BOUNDARY-CONTRACT.md:353-367)

B3. The `_build_attestation` factory is underscore-prefixed and is not re-exported from the persistence package. But the public boundary is not fully correct: `ArchiveAdmissionAttestation` is a publicly exported dataclass with a caller-usable constructor, and the low-level verifier is publicly exported too. A caller can create a detached attestation-shaped object; the archive API does not accept or store it, but the public helper can validate its byte/hash bindings without proving archive issuance—and can omit identity checks as noted in B1. The archive read API remains archive-backed; the detached-object/public-verifier boundary needs to be made unambiguous and safe. (attestation.py:66-88, 91-108, 125-153; persistence/__init__.py:50-57, 143-148; reference.py:898-933)

B4. The rollback test is sufficient to demonstrate rollback after SRC-01 and raw bytes have been written: the injected clock failure occurs after those writes, and assertions check that SRC-01, bytes, and attestation are absent afterward. The extended snapshot/restore includes the archive’s raw blobs, version data, tombstone state, and attestations. (test_m61_archive_attestation.py:154-173; reference.py:716-765, 856-888)

Re-checks:
- `admitted_at`: generated inside admission via the archive clock; `admit_source` has no timestamp parameter. The constructor’s clock injection is available for deterministic tests. (reference.py:512-525, 769-771, 875-885; QAD-M5.2-PERSISTENCE-BOUNDARY-CONTRACT.md:138-144)
- Caller cannot override `admitted_at` through `admit_source`; the test checks that such an argument raises `TypeError`. (test_m61_archive_attestation.py:102-109)
- Immutability: the attestation is a frozen dataclass, and the test checks mutation raises `FrozenInstanceError`. (attestation.py:66-88; test_m61_archive_attestation.py:121-127)
- Atomic SRC-01 + bytes + attestation creation: the archive snapshots before writing and restores on any `BaseException` within the admission block. (reference.py:716-765, 856-888; test_m61_archive_attestation.py:154-173)
- No new M4A canonical schema: the attestation is explicitly non-canonical operational metadata; the design reconciliation retains the 68-schema boundary. (attestation.py:3-6, 66-73; QAD-M5.2-PERSISTENCE-BOUNDARY-CONTRACT.md:134-150; QAD-M6.0-DESIGN-GATE-RECONCILIATION.md:97, 273)
- Mandatory combined backdating fixture: present with `AS_OF 2026-01-01`, `retrieval_date 2025-12-01`, and archive admission `2026-02-01`; it expects `UNAVAILABLE_FOR_SEALED_PIT`. (test_m61_archive_attestation.py:200-216; eligibility.py:84-86)

BLOCKING: Before M6.2, make the public verification path require authoritative `source_id` and `source_ref` (or remove/privatize the bypassable helper), and prevent detached caller-created attestations from being confused with archive-issued proof. Also stop classifying generic `list_versions` history as SRCV-01 evidence; classify SRCV-only only from actual SRCV-01 records.
