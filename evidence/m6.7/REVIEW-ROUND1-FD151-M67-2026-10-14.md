## MATERIAL FINDINGS (as reported by the reviewer)

1. **Untrusted resolver injection can mint proof and durable SUCCESS.** Evidence:
   `qad/m6/orchestration.py:1279` passes the public `proof_resolver=` parameter to
   `provider.execute` (lines 1349–1350) and `qad/m6/research_contract.py:523–528` accepts a
   structurally matching `ProofVerification` when `verified is True`; the repro returned durable
   SUCCESS although neither claimed evidence reference existed. Smallest correction: do not accept
   arbitrary resolver implementations from ordinary callers as proof authority; keep the public
   default fail-closed and expose approved resolver injection only through a trusted orchestration
   capability or test harness.
2. **The public atomic writer accepts fabricated result identity without proof or execution.**
   Evidence: a direct `finalize_success_attempt_atomic(...)` call persisted `SUCCESS` with hash
   `ffff…ffff` and `mock://not-executed/forged`; `qad/m6/ledger.py:1211–1215` checks only that
   `result_sha256` is non-empty and the method accepts raw hash/ref parameters. Smallest
   correction: restrict the low-level writer to an orchestration-only capability, or make it
   accept and validate a proof-bound result object and recompute its digest.
3. **New-run creation can persist request/run identity mismatches and partial candidate state.**
   Evidence: `qad/m6/orchestration.py:1328–1332` resolves/creates using supplied
   `create_run_kwargs` and then loads `resolution.ledger_id`, without validating the new record
   against the request before proceeding. Observed:
   ```
   ledger_id_mismatch_exception= LedgerNotFound: ledger run 'L-WANTED' not found
   ledger_id_mismatch_runs= ['L-OTHER'] ; ledger_id_mismatch_target_exists= False

   request_id_mismatch_exception= RetryPolicyError: SUCCESS refused: the result's request_id
       'REQ-BADCREATE' is not bound to the target ledger run 'L-WANTED' (request_id='REQ-WRONG')
   request_id_mismatch_state= ('REQ-WRONG', 0,
       ['SC-16878b5c7e799454b6c25a65','SC-7735b48b05ec710791bc2687'],
       [('SC-16878b5c7e799454b6c25a65','DEFERRED'),('SC-7735b48b05ec710791bc2687','DEFERRED')], None)
   ```
   Smallest correction: preflight all request-bound `create_run_kwargs` fields before creating a
   run; after resolving, confirm the record and ledger ID match before invoking the provider or
   source bridge.
